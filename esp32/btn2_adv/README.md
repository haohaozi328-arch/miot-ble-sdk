# 米家无线开关（双键版，XMWXKG01YL）可绑定固件 —— ESP32-C3

**可以直接编译烧录、被米家 App 正常添加、两个按键的事件都能上报的完整固件工程。**
与 [`../btn1_adv`](../btn1_adv)（单键版）同一套骨架，只有 PID、键位载荷、按键路数不同。

> **2026-11-14 实机验收**（MAC `10:00:3B:CE:5B:03`，为当时临时派生的测试 MAC）：米家添加一次过
> （`REGISTER COMPLETE 0x11` → `bound=1`），左键单击 `0x4E0C key=1`、双击 `0x4E0D key=1`
> 均立刻广播并重复 2.5s。右键（GPIO3）与长按按下面清单自测即可。

- 目标芯片：ESP32-C3（USB-Serial/JTAG 直连，一根 Type-C 线即可）
- 模拟型号：米家无线开关（双键版）`XMWXKG01YL`，PID **0x1949**
- 上报内容：常态电量心跳（`0x100A` u8 %）+ 按键事件（`0x4E0C` 单击 / `0x4E0D` 双击 /
  `0x4E0E` 长按），**载荷 1 字节 = 键位：1=左键，2=右键**
- 通道：MiBeacon V5 加密广播（网关用）+ 0xFE95 GATT（手机用，spec 3.1020 / 3.1003）
- 按键事件只走广播 —— 真机也是这样，按键值不进 GATT

## 接线

| 键位 | 引脚 | 怎么按 |
|---|---|---|
| 左键（载荷 1） | **GPIO9**（板载 BOOT） | 直接按板上的 BOOT |
| 右键（载荷 2） | **GPIO3** | 外接轻触开关一端接 GPIO3、一端接 GND；<br>没有开关就拿杜邦线/镊子把 GPIO3 和 GND 碰一下 |

两键都支持**单击 / 双击 / 长按**；左键按住 5 秒 = 恢复出厂（擦 NVS）。

> GPIO3 上电时不是 strapping 脚，可以放心接按键；别把右键改到 GPIO2/8/9，
> 那是启动配置脚，上电被拉低会进下载模式。

## 编译

```bash
cd esp32/btn2_adv
idf.py build
```

## 烧录（首次必须整片擦除）

```bash
idf.py -p COM6 erase-flash       # ★首次烧录必须整片擦除，否则残留 NVS 会串身份
idf.py -p COM6 flash monitor
```

## 米家添加

1. 米家 → 右上角 **+** → **添加设备** → 附近设备出现「米家无线开关」（双键）
2. 点它；App 提示「请短按设备按键」时短按一下 BOOT
3. 串口依次出现：`phone connected` → `REGISTER COMPLETE (result 0x11)` → `bound=1`

## 验收清单

| 步骤 | 你应该看到 | 判据 |
|---|---|---|
| ① 烧完复位 | `host synced … bound=0`，广播 FC `70 2A` | 未绑定 + solicited |
| ② 米家添加 | `REGISTER COMPLETE (0x11)` → `bound=1` | 云端下发 did 才算成 |
| ③ 左键单击 | `K1(左键) -> event 0x4E0C CLICK key=1` | 事件帧 2.5s 快广播（30~50ms 间隔） |
| ④ 左键双击 / 长按 | `0x4E0D DOUBLE` / `0x4E0E HOLD`，`key=1` | 两键的事件对象相同，只看载荷 |
| ⑤ 右键单击 | `K2(右键) -> event 0x4E0C CLICK key=2` | 载荷变 2 就说明键位对了 |
| ⑥ 右键双击 / 长按 | `key=2` | 右键长按**不会**恢复出厂（只有左键会） |
| ⑦ 米家设备日志 | 出现点击记录 | 云端收到事件 |
| ⑧ 自动化条件 | 「如果」里出现单击/双击/长按 | 云端同步有延迟，见下方 FAQ |

## 与单键版（btn1_adv）的差异

| 项 | 单键 0x2387 | 双键 0x1949（本工程） |
|---|---|---|
| PID / 设备名 | 0x2387 / XMWXKG01CM | 0x1949 / XMWXKG01YL |
| 按键输入 | BOOT 一路 | BOOT + GPIO3 两路 |
| 事件载荷 | 恒 1 | 1=左键，2=右键 |
| 事件对象 | 0x4E0C / 0x4E0D / 0x4E0E | 完全相同 |
| 恢复出厂 | BOOT 按住 5s | 仅左键（GPIO9）按住 5s |
| NVS 命名空间 | `btn1` | `btn2` |

## FAQ

**Q：米家「附近设备」里根本扫不到这台？**
本工程**不覆盖 MAC**，用的是芯片出厂物理 MAC。米家按 MAC 认设备：同一个 MAC 只要
在账号里已经绑过（比如这颗芯片之前跑 `t3pro_adv` 绑成了温湿度计 3 Pro），附近设备
列表就会把它当成"那台已添加的设备"直接过滤，怎么扫都出不来。

先按这个顺序排：
1. `idf.py -p COM6 erase-flash` 清掉残留 NVS（旧 did 会让米家认为"已添加过"）
2. 米家里把同名的旧设备删掉，或换一颗没绑过的板子
3. 还不行就临时派生一个专属 MAC（`docs/troubleshooting.md` Q2 第 6 条，三行代码）

**Q：右键怎么按都没反应？**
检查 GPIO3 是否真被拉到 GND（用万用表量，或换一根线）。悬空时内部上拉让电平恒高，
固件认为"没按"。另外 `idf.py monitor` 里能看到 `K2(右键)` 才算固件收到了。

**Q：右键也能恢复出厂吗？**
不能，只有 GPIO9（左键）按住 5 秒会擦 NVS —— 真机复位孔在机身，双键版也是左键长按。

**Q：两个键同时按住？**
一次只处理一个事件：正在等双击的 400ms 内按另一个键会被忽略。
连续发两个不同键的事件，请间隔 2.5s 以上（事件帧本身要重复广播 2.5s）。

**Q：自动化里找不到触发条件？**
云端要等设备上报过事件才在自动化编辑器里出条件，且同步有轮询延迟。
先按几下让设备日志有记录 → 杀掉米家 App 重开 → 还不行等 10~15 分钟 → 最后试网关断电重启。
