# 米家人体传感器2（RTCGQ02LM）小白版固件 —— ESP32-C3

**一根 Type-C 线、三条命令、按一下 BOOT 就能用。**

烧完这块板子在你的米家里就变成一台「人体传感器2」：米家 App 能添加它、
设备页能看「有人移动 / 无人 / 光照 / 电量」，也能拿它当自动化触发条件
（有人经过 → 开灯）。

- 目标芯片：ESP32-C3（USB-Serial/JTAG 直连）
- 模拟型号：人体传感器2 `RTCGQ02LM`，PID **0x0A8D**
- 上报内容：移动+光照 `0x000F` / 无人时长 `0x1017` / 电量 `0x100A`
- 通道：MiBeacon V5 加密**广播**（网关收） + 0xFE95 GATT（只用于绑定）

> 只想知道原理不用烧板子：看 [`../t3pro_adv/README.md`](../t3pro_adv/README.md)。
> 本工程跟 `door_adv` 一个骨架，只有 PID / 广播对象不同，代码里都标了 ★。

---

## 一、动手前先看这三行

| 你要做的 | 怎么做 |
|---|---|
| 上报「有人移动」 | **短按一次 BOOT**（60 秒没新动作会自动回「无人」） |
| 恢复出厂（重新添加） | **按住 BOOT 5 秒**（串口打印「恢复出厂」，然后自动重启） |
| 看它有没有在干活 | 串口每按一次都有 `>>> 按键触发：有人移动（0x000F = 1 / 光照 1）` |

## 二、编译（二选一）

**装了 ESP-IDF v6.0：**

```bash
cd esp32/motion_adv
idf.py build
```

**没装 IDF，用 Docker（推荐，不用配环境）：**

```bash
docker run --rm -v "D:/workspace/temp/miot-ble-sdk:/project" -w /project/esp32/motion_adv \
  espressif/idf:v6.0 bash -c "idf.py build"
```

## 三、烧录（第一次一定要擦）

```bash
idf.py -p COM6 erase-flash
idf.py -p COM6 flash monitor
```

**为什么要 `erase-flash`**：NVS 里如果留着别的工程的绑定身份，板子会以「已绑定」
状态广播，米家的添加列表会**直接把它过滤掉**，表现就是「怎么都扫不到」。

烧完串口应该是这样：

```
I (312) MOTION: ===== 人体传感器2 小白版（RTCGQ02LM / 0x0A8D）=====
I (313) MOTION: 用法：米家 App → + → 添加设备 → 点 RTCGQ02LM → 绑定
I (314) MOTION:       短按 BOOT = 有人移动一次   长按 5 秒 = 恢复出厂
I (509) MOTION: 协议栈就绪  MAC 10:00:3B:CE:5E:02  未绑定（等待米家添加）
```

`未绑定` 就对了 —— 说明它在等 App 来添加。

## 四、在米家里添加

1. 米家 App → 右上角 **+** → **添加设备**
2. 等「附近设备」里出现 **RTCGQ02LM**（通常 3~10 秒）
3. 点它 → 等自动绑定 → 串口打印：

```
I (xxx) MOTION: 手机连上来了（广播已暂停）
I (xxx) MOTION: 绑定身份已保存（did xx xx xx xx）
I (xxx) MOTION: *** 绑定成功，广播切到已绑定形态 ***
```

4. 回到设备页，**短按一次 BOOT** → 页面变「有人移动」；放着不动 60 秒 → 自动回「无人」

> 添加时如果一直停在「正在连接」，把手机靠近板子（半米内）再点一次；
> 串口侧**一个 `手机连上来了` 都没有**，说明连接压根没建立，不是握手失败。

## 五、看现象：三种「成功」的样子

| 现象 | 说明什么 | 判据（串口） |
|---|---|---|
| 附近设备里出现 RTCGQ02LM | 广播 + 未绑定形态对了 | `未绑定（等待米家添加）` |
| 添加完成后设备页能进 | 绑定成功（云下发了 did） | `绑定身份已保存` + `绑定成功` |
| 短按 BOOT 页面变「有人移动」 | 广播 → 网关 → 云端全链路通 | `>>> 按键触发：有人移动` |

第三种要**网关在线**才有。页面显示「未连接蓝牙网关」时先别急着改代码 ——
拔插一次网关电源、重启 App，通常就恢复了。

## 六、改参数（都在 `main/app_main.c` 顶部）

| 想改什么 | 位置 | 说明 |
|---|---|---|
| 型号 / PID | `MOTION_PID` / `MOTION_NAME` | 换型号要同步改广播对象 |
| 广播对象 | `build_frame()` 里的 `case 0/1/2` | 0x000F 移动+光照 / 0x1017 无人秒数 / 0x100A 电量 |
| 设备 MAC | `BASE_MAC_B4` | **每个工程必须不一样**（btn2=5B, scale=5C, door=5D, motion=5E） |
| 「无人」回落时间 | `NO_MOTION_MS` | 默认 60000ms |
| 广播间隔 | `ADV_PERIOD_MS` | 默认 6 秒轮换一帧 |
| 平常是否可连接 | `ADV_CONN_ALWAYS` | 1=随时能连（默认）；0=只在按键后 2 分钟内可连（真机行为） |

**接真实 PIR 传感器**：把 `btn_task` 里那段按键切换换成你的 GPIO 读取即可：

```c
if (gpio_get_level(PIR_GPIO)) {      /* 检测到人 */
    v_motion = 1;
    s_last_motion_ms = now_ms();
    s_ev_left = EVENT_REPEAT;        /* 补发几帧，剩下逻辑不用动 */
}
```

## 七、常见问题

**Q：米家里扫不到这块板子？**
① 先 `erase-flash` 再烧（最常见）；② 确认 `BASE_MAC_B4` 跟别的工程不同（米家按 MAC 去重）；
③ 手机蓝牙开着，站近一点。

**Q：能添加，但设备页一直是「--」或者「未连接蓝牙网关」？**
人体传感器是**纯广播设备**：页面数据走「广播 → 网关 → 云端」。
网关不在线时页面就是空的，这是环境问题，不是固件问题。

**Q：为什么「有人」60 秒后就变「无人」了？**
真机就是这么工作的（PIR 只在有人时上报，之后靠无人时长心跳收敛）。想让它一直
保持「有人」，把 `NO_MOTION_MS` 调大，或者在按键里每次都刷新 `s_last_motion_ms`。

**Q：按 BOOT 页面没反应？**
先看串口有没有 `>>> 按键触发`。有 → 固件已经发出去了，等网关（通常 1~5 秒）。

## 八、已知边界

- **`0x000F` 的第 3 字节固定 0**（真机是保留位），只发 b1=移动 / b2=光照。
- **没有「按键」对象 `0x1001`**：真机长按会有一次按键上报，本工程把长按留给恢复出厂。
- **光照是常量**（`v_light = 1`），接光敏电阻时替换成读数即可。
