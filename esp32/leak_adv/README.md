# 米家水浸传感器（SJWS01LM）小白版固件 —— ESP32-C3

**一根 Type-C 线、三条命令、按一下 BOOT 就能用。**

烧完这块板子在你的米家里就变成一台「水浸传感器」：米家 App 能添加它、
设备页能看「是否漏水 / 电量」，还能拿它当自动化触发条件（漏水 → 关水阀 / 响小爱）。

- 目标芯片：ESP32-C3（USB-Serial/JTAG 直连）
- 模拟型号：水浸传感器 `SJWS01LM`，PID **0x0863**
- 上报内容：漏水状态 `0x1014`（0=正常 / 1=漏水） / 电量 `0x100A`
- 通道：MiBeacon V5 加密**广播**（网关收） + 0xFE95 GATT（只用于绑定）

> 只想知道原理不用烧板子：看 [`../t3pro_adv/README.md`](../t3pro_adv/README.md)。
> 本工程跟 `door_adv` 一个骨架，只有 PID / 广播对象 / 按键动作三处不同，代码里都标了 ★。
>
> **2026-11-14 实机验收通过**：米家添加一次过（`REGISTER COMPLETE 0x11`，did 已存）→
> 短按 BOOT 连发 3 帧 `0x1014 = 1`（漏水），设备页转「漏水」并进「感应记录」。

## 一、动手前先看这三行

| 你要做的 | 怎么做 |
|---|---|
| 漏水 / 水退了 | **短按一次 BOOT**（每按一次在「漏水」和「正常」之间切换） |
| 恢复出厂（重新添加） | **按住 BOOT 5 秒**（串口会打印「恢复出厂」，然后自动重启） |
| 看它有没有在干活 | 串口日志里每按一次都有 `>>> 按键触发：检测到漏水（0x1014 = 1）` |

不用接线、不用改代码、不用装别的库。

## 二、编译（二选一）

**装了 ESP-IDF v6.0：**

```bash
cd esp32/leak_adv
idf.py build
```

**没装 IDF，用 Docker（推荐，不用配环境）：**

```bash
docker run --rm -v "D:/workspace/temp/miot-ble-sdk:/project" -w /project/esp32/leak_adv \
  espressif/idf:v6.0 bash -c "idf.py build"
```

## 三、烧录（第一次一定要擦）

```bash
idf.py -p COM6 erase-flash
idf.py -p COM6 flash monitor
```

Docker 版把 `idf.py` 换成对应的 `docker run ... idf.py` 即可。

**为什么要 `erase-flash`**：NVS 里如果留着别的工程的绑定身份，板子会以「已绑定」
状态广播，米家的添加列表会**直接把它过滤掉**，表现就是「怎么都扫不到」。
换工程、改 PID、重新添加之前，一律先擦。

烧完串口应该是这样：

```
I (312) LEAK: ===== 水浸传感器 小白版（SJWS01LM / 0x0863）=====
I (313) LEAK: 用法：米家 App → + → 添加设备 → 点 SJWS01LM → 绑定
I (314) LEAK:       短按 BOOT = 漏水/解除 切换一次   长按 5 秒 = 恢复出厂
I (509) LEAK: 协议栈就绪  MAC 10:00:3B:CE:5F:03  未绑定（等待米家添加）
```

`未绑定` 就对了 —— 说明它在等 App 来添加。

## 四、在米家里添加

1. 米家 App → 右上角 **+** → **添加设备**
2. 等「附近设备」里出现 **SJWS01LM**（通常 3~10 秒）
3. 点它 → 等自动绑定 → 串口打印：

```
I (xxx) LEAK: 手机连上来了（广播已暂停）
I (xxx) LEAK: 绑定身份已保存（did xx xx xx xx）
I (xxx) LEAK: *** 绑定成功，广播切到已绑定形态 ***
```

4. 回到设备页，**短按一次 BOOT** → 页面变成「漏水」（并进「感应记录」），再按一次 → 「正常」

> 添加时如果一直停在「正在连接」，把手机靠近板子（半米内）再点一次；
> 串口侧**一个 `手机连上来了` 都没有**，说明连接压根没建立，不是握手失败。
> 首次添加后若设备页一直转「蓝牙连接中」，**杀掉 App 重开**即可（老固件的已知现象，
> 本工程已把按键后唤醒窗口设成 2 分钟，通常不需要）。

## 五、看现象：三种「成功」的样子

| 现象 | 说明什么 | 判据（串口） |
|---|---|---|
| 附近设备里出现 SJWS01LM | 广播 + 未绑定形态对了 | `未绑定（等待米家添加）` |
| 添加完成后设备页能进 | 绑定成功（云下发了 did） | `绑定身份已保存` + `绑定成功` |
| 短按 BOOT 页面变「漏水」 | 广播 → 网关 → 云端全链路通 | `>>> 按键触发：检测到漏水` |

第三种要**网关在线**才有。页面显示「未连接蓝牙网关」时先别急着改代码 ——
拔插一次网关电源、重启 App，通常就恢复了（这是环境侧的老毛病，几台设备都复现过）。

> **电量显示 `--`**：电量走心跳帧，网关不一定即时上报，等一两轮心跳（约 1 小时）
> 或重启网关后会补上，不影响漏水事件本身。

## 六、改参数（都在 `main/app_main.c` 顶部）

| 想改什么 | 位置 | 说明 |
|---|---|---|
| 型号 / PID | `LEAK_PID` / `LEAK_NAME` | 换型号要同步改广播对象，见下一行 |
| 广播对象 | `build_frame()` 里的 `case 0/1` | 0x1014 漏水状态 / 0x100A 电量 |
| 设备 MAC | `BASE_MAC_B4` | **每个工程必须不一样**，米家按 MAC 去重（btn2=5B, scale=5C, door=5D, motion=5E, leak=5F） |
| 广播间隔 | `ADV_PERIOD_MS` | 默认 4 秒轮换一帧 |
| 事件补发次数 | `EVENT_REPEAT` / `EVENT_GAP_MS` | 默认连发 3 次、间隔 400ms |
| 平常是否可连接 | `ADV_CONN_ALWAYS` | 1=随时能连（默认，方便添加）；0=只在按键后 2 分钟内可连（真机行为） |

**接真实水浸探针**：把 `btn_task` 里那段按键切换换成你的 GPIO 读取即可：

```c
uint8_t now = gpio_get_level(PROBE_GPIO) ? LEAK_WET : LEAK_NORMAL;
if (now != v_leak) {
    v_leak = now;
    s_ev_left = EVENT_REPEAT;   /* 状态变化时补发几帧，剩下的逻辑不用动 */
}
```

（真机探针是两根电极：进水导通 → 拉低/拉高，按你的硬件极性改 `LEAK_WET` 那一侧即可。）

## 七、常见问题

**Q：米家里扫不到这块板子？**
① 先 `erase-flash` 再烧（最常见）；② 确认 `BASE_MAC_B4` 跟别的工程不同
（同一块板子烧过别的工程、且那个 MAC 已经被你的账号绑过，米家会按 MAC 去重）；
③ 手机蓝牙开着，站近一点。

**Q：能添加，但设备页一直是「--」或者「未连接蓝牙网关」？**
水浸传感器是**纯广播设备**：页面数据走「广播 → 网关 → 云端」，跟手机连不连没关系。
所以必须有一个在线的蓝牙网关（小爱音箱 / 蓝牙 Mesh 网关）且它愿意收这个品类。
网关不在线时页面就是空的，这是环境问题，不是固件问题。

**Q：按 BOOT 页面没反应？**
先看串口有没有 `>>> 按键触发`。有 → 固件这边已经发出去了，等网关（通常 1~5 秒）；
没有 → 板子跑的不是本工程固件（或者按键坏了）。

**Q：换回别的工程，怎么又扫不到了？**
每个工程的 MAC 和后缀都不同，擦一下再烧即可（`erase-flash`）。

## 八、已知边界

- **只有「漏水 / 正常」两态**，没有「探针断开」这类故障态；真机断电/离线时 App 显示
  「设备离线」由云端按心跳判定，本工程不模拟。
- **电量是常量**（`v_batt = 95`），接真实电池分压时替换成读数即可。
- **一次按键只报一次事件**，不做「水面抖动过滤」；真机是持续浸水期间周期性上报。
- **没有 0x1001 按键对象**：真机长按有一次按键上报，本工程把长按留给恢复出厂。
