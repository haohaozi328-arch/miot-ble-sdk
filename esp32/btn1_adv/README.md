# 小米无线开关（蓝牙版，XMWXKG01CM）可绑定固件 —— ESP32-C3

**这是一个可以直接编译烧录、被米家 App 正常添加、按键事件能上报到云端的完整固件工程。**
2026-11-14 实测：米家添加成功（`REGISTER COMPLETE 0x11`）→ 短按 BOOT 事件广播发出
（`0x4E0C` 单击 / `0x4E0D` 双击 / `0x4E0E` 长按）→ 米家设备日志出现点击记录。

- 目标芯片：ESP32-C3（USB-Serial/JTAG 直连，一根 Type-C 线即可）
- 模拟型号：小米无线开关（蓝牙版）`XMWXKG01CM`，PID **0x2387**（国区 pdid 9095）
- 上报内容：常态电量心跳（`0x100A` u8 %）+ 按键事件（单击/双击/长按，载荷 1B 按键号）
- 通道：MiBeacon V5 加密广播（网关用）+ 0xFE95 GATT（手机用，spec 3.1020 / 3.1003）
- 板载 BOOT 键 = 被模拟的按键本身：
  - **单击**（<1s 松开）→ `0x4E0C`
  - **双击**（400ms 内两次短按）→ `0x4E0D`
  - **长按**（按住 ≥1s）→ `0x4E0E`
  - **按住 5 秒** → 恢复出厂（擦 NVS）

## 编译

```bash
cd esp32/btn1_adv
idf.py set-target esp32c3        # 如果用 sdkconfig.defaults 已预设则可跳过
idf.py build
```

## 烧录（首次必须整片擦除）

```bash
idf.py -p COM6 erase-flash       # ★首次烧录必须整片擦除，否则残留 NVS 会串身份
idf.py -p COM6 flash monitor
```

## 米家添加

1. 米家 → 右上角 **+** → **添加设备** → 附近设备出现「小米无线开关」
2. 点它；App 提示「请短按设备按键」时短按一下 BOOT
3. 串口依次出现：`phone connected` → `REGISTER COMPLETE (result 0x11)` → `bound=1`

## 验收清单

| 步骤 | 你应该看到 | 判据 |
|---|---|---|
| ① 烧完复位 | `host synced … bound=0`，广播 FC `70 2A` | 未绑定 + solicited |
| ② 米家添加 | `REGISTER COMPLETE (0x11)` → `bound=1` | 云端下发 did 才算成 |
| ③ 单击测试 | `BOOT -> event 0x4E0C CLICK (repeat 2500ms)` | 事件帧 2.5s 快广播 |
| ④ 米家设备日志 | 该设备的日志流出现「单击」记录 | 云端已收到事件 |
| ⑤ 双击/长按 | `0x4E0D DOUBLE` / `0x4E0E HOLD` | 三种事件都上云 |
| ⑥ 自动化条件 | 「自动化」→「如果」→ 这台设备出现单击/双击/长按 | 见 FAQ，通常要等云端同步 |

## 与云端产品定义对比

> 2026-11-14 核对。云端侧数据源：`miot-spec.org` 公开注册表全量 48264 个实例、
> ble_monitor 官方解析器（对象语义的第三方实现）、官方《MiBeacon 配对》文档、真机实测。

| 层面 | 云端/官方 | 本固件 | 一致？ |
|---|---|---|---|
| **公开 spec 注册表** | `miot-spec.org` 上**没有** XMWXKG01CM/01YL 的实例——BLE 按键产品的产品定义是云端内部分发（App/网关私有接口拉取），公开查不到 | GATT spec 表按 Gateway3/真机行为定：3.1020 按键配置 u16 RW、3.1003 电量 u8 R | ⚠️ 无法逐项核对（见 FAQ） |
| **单击对象** | `0x4E0C`（ble_monitor：固定输出 "single press/toggle"，**不解析载荷**） | `0x4E0C`，载荷 1B=按键号（多键设备区分左右键，单键恒 1） | ✓ 语义对齐 |
| **双击对象** | `0x4E0D` | `0x4E0D`，载荷 1 | ✓ |
| **长按对象** | `0x4E0E` | `0x4E0E`，载荷 1 | ✓ |
| **电量对象** | `0x100A` u8 %（ble_monitor 由它线性推算 2.2~3.1V 电压） | `0x100A` u8 % | ✓ |
| **配对确认** | 官方文档：设备确认（按键）时 MiBeacon 置 `solicited=1`，App 检测到才发起连接 | 未绑定恒 `0x2A`（v2\|registered=0\|authMode=2\|solicited=1） | ✓ |
| **绑定后广播** | 真机已注册态 FC=`0x59`（v5\|registered\|authMode=2） | `0x59`，事件期间临时升 `0x5B` | ✓ |
| **事件上报方式** | 网关按广播边沿判定（轮询窗口短） | 事件帧立刻发出并重复 2.5s、快广播 30~50ms | ✓（实测双键版通过） |
| **自动化条件来源** | 云端产品定义 + 设备历史事件，绑定后延迟出现 | 固件只管把事件发出去 | —（App/云端侧行为） |

**结论：对象层完全对齐公开可查的官方语义；唯一无法核对的 GATT spec 表（3.1020/3.1003）
也是"云端不可查"本身导致的——公开 spec 注册表没有这个型号。**

## FAQ

**Q：自动化里找不到这台设备的触发条件？**
正常。云端要等设备上报过事件才会在自动化编辑器里出条件，且同步有轮询延迟。
实测经验（双键版 2026-11-04、单键版 2026-11-14）：先按几下 BOOT 让设备日志有记录 →
完全杀掉米家 App 重开 → 还没有就等 10~15 分钟 → 实在不行把音箱网关断电重启。

**Q：按 BOOT 没反应？**
固件里 BOOT 是 100ms 轮询的运行期按键任务，≥60ms 才算有效按压。**单击判定要等
400ms 的双击判定窗口**，所以单击后事件不会瞬间发出，最多延迟 0.4s，属正常。

**Q：单击和长按的边界？**
<1s = 单击；1~5s = 长按；≥5s = 恢复出厂（设备会重启、回到未绑定态）。
想要不同的阈值改 `btn_task` 里的 `1000` / `5000`。

**Q：删除设备后再也扫不到了？**
先 `idf.py -p COM6 erase-flash`（或长按 BOOT 5 秒）清掉绑定身份。

## 踩过的坑（改代码前先读这几条）

1. **按键事件必须立刻发 + 重复 2.5s**。网关按广播边沿判定，事件如果跟着普通心跳
   周期走，会落在网关两次轮询之间被整帧漏掉——这就是"设备日志没有点击记录"的
   最常见原因。快广播（30~50ms）+ 2.5s 重复是实测可过的参数。
2. **未绑定 hello 帧必须带 solicited 位（FC 高字节 `0x2A`）**。缺位时 App 点添加
   后永远不发起连接，30s 报「连接超时」，设备端一个 CONNECT 事件都没有。
3. **广播必须用无 MAC 形态（`miot_beacon_frame_v5_nomac`）**，同 t3pro_adv。
4. **NVS 命名空间必须独立**（本工程 `btn1`）。复用 `multi_dev`/其他工程的名字会
   读到别的设备的 did/bind_key，米家把数据记到别人名下。
5. **帧内 MAC 字段是 LSB 序**。nonce = mac||pid||cnt||counter_ext，序错了加密帧
   永远解不开，表现为设备在线、广播正常、云端永远没有数据。
6. **自动化条件延迟不是固件问题**。对象号、加密、密钥全对的情况下，条件出不来
   是云端同步周期，先杀 App 重开、再等轮询、最后才重启网关。
