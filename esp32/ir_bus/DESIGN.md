# ir_bus：把红外当「嘴」、把上云当「眼」的一种做法

> 这是一份**方案参考**，不是产品说明书。它给出一条把「小爱音箱的红外」和「米家 BLE 广播」
> 拼成闭环的思路，以及型号选型和边界判断，供你按自己的场景取舍——用不用、用哪一半，都可以。
>
> 操作步骤见 [README.md](README.md)；红外码表与协议细节见 [ir_lib/](ir_lib/)。

---

## 0. 一句话

小爱音箱的红外是**单向下行**，米家 BLE 广播是**单向上行**。两者拼起来才闭环：

```
     下行（嘴）： 米家云 / 语音 / 自动化
                    ↓
              小爱音箱（内置红外 LED，38~40kHz）
                    ↓  空气
              IR Hub（VS1838B 接收，只干这一件事）
                    ↓  BLE / ESP-NOW
              Node × N（继电器执行 + 状态回传）
                    ↓
              上行（眼）：MiBeacon 加密广播 → 青萍网关 → 云 → App / 自动化
```

**红外解决"下达"，上云解决"确认"。** 只做前者最省，要闭环才需要后者。

## 1. 三种架构，按设备复杂度选

| | A. 小爱直发 | B. 小爱发暗号 + ESP32 翻译 | C. 小爱学习自定义键 |
|---|---|---|---|
| 谁发真实控制码 | 小爱音箱 | **ESP32**（自己带 940nm LED） | 小爱音箱 |
| 适合 | 电视、机顶盒、投影、风扇 | **空调、风扇、米家码库没有的设备** | 任意"键帧固定"的设备 |
| 需要真实遥控器 | 否（用米家码库） | 建议有（学 raw 码） | **必须**（对着音箱学） |
| 能否精确控温 | — | **能**（构造状态帧） | ❌ 只能复现录制时那一帧 |

本仓库的参考固件只实现了 **A**；B、C 是思路说明，供你判断要不要往下走。

### A. 小爱直发

小爱按米家码库发码，Hub 只负责解码 → 转成 BLE 指令。参考实现里已验证：索尼电视 `dev=0x01 cmd=0x15/0x12/0x13`。

**局限**：只能用米家码库里有的品牌和键；空调那种"每键带全状态"的码不适合当暗号。

### B. 小爱发暗号 + ESP32 翻译

小爱只发一条**固定的简单码**（比如电视"音量+"），Hub 收到后**自己发真正复杂的码**：

```
"小爱同学，打开电视"  →  SIRC cmd=0x12  →  Hub 收到
                                              ↓ 查表
                                        重放空调 raw 码（开机+26℃+制冷）
```

两条路线：

| 路线 | 做法 | 门槛 | 备注 |
|---|---|---|---|
| **B1. 学 raw 重放** | 用 VS1838B 收真实遥控器的码 → 存 NVS → 用 LED 原样重放 | 低 | 不懂协议也能控任何设备，**最通用** |
| B2. 协议构造 | 移植 IRremoteESP8266 的空调编码（格力/美的/海尔/大金…100+ 品牌） | 高 | 能精确调温、改模式，但要自己改 RMT 发送层 |

**B1 是这个思路里最值钱的一点**：不需要破解空调协议。**录一条 raw 码约 100~300 个 timing（1~2KB），NVS 能存几十条**，等价于一个博联 RM Pro。

### C. 小爱学习自定义键

小爱音箱 Play 增强版支持"红外遥控 → 自定义遥控器 → 学习"（把真实遥控器对准音箱按一下）。学到的键会出现在米家面板里，可以被语音和自动化触发。

**局限**：学的就是"那一次按下发出的完整帧"。空调遥控器每个键都带全状态，所以学到的只是录制当时的状态，**不能当可复用的状态机**。

## 2. 品类可行性矩阵

| 品类 | 载波 | 典型码型 | 与 VS1838B(38k) | 能当暗号 | 适合架构 | 备注 |
|---|---|---|---|---|---|---|
| 电视 索尼 | 40kHz | SIRC12/15/20 | 差 2kHz | ✅ | **A** | 短码、键多、46 键公开码表 |
| 电视 创维/海信/TCL | 38kHz | NEC | 正好 | ✅ | **A** | 距离比索尼更稳 |
| 机顶盒 | 38kHz | NEC | 正好 | ✅ | **A** | 键少但极稳定 |
| 投影仪 | 38kHz | NEC / 私有 | 正好 | ✅ | A 或 B | 私有码走 B1 |
| **电风扇** | 38kHz | NEC / 私有 | 正好 | ✅（电源是 toggle） | **A 或 B1** | 风速是多档离散码，正好当多条指令 |
| **空调** | 38kHz | 私有长帧（100~200 位） | 正好 | ❌ **不稳定** | **B1 / B2** | 每键带完整状态，同键不同码 |
| **自定义 / 冷门设备** | 任意 | raw | 取决于载波 | 取决于设备 | **B1 + C** | 学 raw 最通用 |
| 红外宝能控的设备 | — | — | — | — | A | 这类没必要自己做 |

### 空调的具体边界

- **能收**：38kHz、码长 100~200 位，RMT 缓冲区要从 96 symbol 加到 512 才装得下。
- **不能当暗号**：遥控器每次按键都发"完整状态帧"（模式+温度+风速+摆风+定时），所以"温度+"在你已经 26℃ 和 28℃ 时发出的是两条不同的码。
- **正确用法**：把它当"被控对象"，而不是"指令源"。小爱只发暗号，空调码由 Hub 自己发（B1 学 raw 或 B2 构造）。
- **别指望 C**：学习只录到一帧，等于固定成"26℃制冷"，改温度还得再学一次。

### 电风扇的具体边界

- 比空调友好得多：电源、风速 1/2/3、摇头、定时都是**固定短码**，可以直接当暗号。
- 唯一的坑：**电源键是 toggle**，所以要用"风速 1"当开、"定时"或"关机"当关，和电视机的 `0x15` 一个道理。

## 4. 这套方案真正的价值：**不需要联网的执行器**

| WiFi 设备的硬伤 | 这套方案 |
|---|---|
| 2.4G 配网，5G 混频经常失败 | 不用配网，上电即用 |
| 路由器连接数上限（20~30 台就吃力） | 不占路由，一个房间 10 个节点也行 |
| 断网就失效、AP 隔离就离线 | 断网照样工作（红外是光，不用网） |
| 装在金属柜 / 弱信号角落就掉线 | 不受信号影响，塞哪都行 |
| 要账号、要云、要固件更新，攻击面大 | 不联网 = 零网络攻击面 |
| 老人 / 访客不会用 App | 一句"打开电视"就行 |

**和"红外宝"的本质差异**：红外宝只能控"本身带红外接收"的电器；老风扇、老热水器、机械开关的灯根本没有红外头，红外宝对它们无能为力。这套方案**红外只当指令总线，末端是继电器断电**，所以能控任何"能拔插头"的东西。

---

## 5. 替代不了什么（别误判）

| WiFi 设备能做 | 这套做不到 |
|---|---|
| 调亮度、色温、风速档位 | 继电器只能通/断；要调档得靠电器自己的红外码（B1 重放） |
| 读实时功率、累计电量 | 要加电流互感器，现在没有 |
| 窗帘停在中途任意位置 | 只能全开 / 全关 |
| 状态秒级实时 | 受 4s 轮播限制，上报有延迟 |
| 断网仍可远程 | 远程仍依赖"家里小爱在线 + 小米云"这条链 |

## 6. 这份参考实现的边界

哪些是你拿来就能跑的，哪些只是文档里的思路，这里说清楚，免得误判。

| 环节 | 情况 |
|---|---|
| 小爱音箱 → VS1838B → SIRC12 解码 | 跑通过（`dev=0x01 cmd=0x15/0x12/0x13`） |
| 8 帧连发去抖 | 跑通过（折叠成 1 次触发） |
| Hub：红外 → BLE 通知 | 跑通过（`<<< RX cmd=0x15`） |
| Node：BLE 指令 → 继电器 → 状态回报 | 跑通过（3/3 稳定） |
| Node 广播带状态（不连接可读） | 跑通过（`状态=通(1)` @ -43dBm） |
| 伪装门窗3 上云 | 跑通过（`bound=1`，`on`/`off` 后 App 门态跟着变） |
| 空调 / 风扇 / 自定义设备的红外发射（B1） | 只有设计说明：需要给 Hub 加发射 LED + raw 学习，代码不在本仓库 |
| 小爱自定义遥控器学习（C） | 属于米家 App 自带功能，固件不需要配合 |

## 7. 硬件清单

| 器件 | 用途 | 接线 | 备注 |
|---|---|---|---|
| ESP32-C3 | Hub / Node | — | 一块板可分时烧两个固件测试 |
| VS1838B | 红外接收 | VCC→3.3V，GND→GND，OUT→**GPIO3** | 38kHz 带通，低有效 |
| 5mm 940nm LED | 红外发射（B1 用） | 阳极串 **100Ω** → GPIO5，阴极 → GND | 建议加 S8050 三极管，GPIO 直驱电流不够 |
| 继电器模块 | 执行 | IN→GPIO4，VCC→5V，GND→共地 | 多数是低电平触发，`RELAY_ACTIVE_LOW` 一行切换 |
| 青萍网关 | 广播上云 | — | 解密 MiBeacon，把状态送到云 |

载波提示：索尼是 40kHz、VS1838B 是 38kHz，近距离能用但远了灵敏度掉。要拉远就换 **TSOP4840**（40kHz）或把接收头用排线引到开阔处。
