# 红外协议笔记（本项目实测相关）

只记录本项目用到的两种协议，以及"为什么能解/会在哪出错"。

## 1. 索尼 SIRC

| 项 | 值 |
|---|---|
| 载波 | **40kHz**（注意不是 38kHz） |
| 编码方式 | 脉宽编码（PWM）：用 mark 长度表示 0/1 |
| 帧头 | mark 2.4ms + space 0.6ms |
| 逻辑 0 | mark 0.6ms + space 0.6ms |
| 逻辑 1 | mark 1.2ms + space 0.6ms |
| 位序 | **LSB first** |
| 帧结构 | 7bit 命令 + 5bit 设备号（12bit），或扩展到 15/20bit |
| 连发 | 按住时每 ~45ms 重复一整帧 |
| 实收段数 | 12bit → 25 段；15bit → 31 段；20bit → 41 段 |

我们实测到的（小爱音箱发，`打开电视`）：

```
NEW SIRC12 dev=0x01 cmd=0x15
```

`dev=0x01` = 电视，`cmd=0x15` = 电源，与 SIRCS 公开命令表一致。

### 为什么 38kHz 接收头也能收 40kHz

VS1838B 是 38kHz 中心、带宽约 ±3~4kHz，40kHz 落在通带边缘：**解调包络不变，
只是增益下降**。近距离完全可用，远距离（>2m）丢帧率会明显上升。

对策（都是收敛在 Hub 一处的事）：
- 换 40kHz 接收头（TSOP4840 / HS0038B）
- 加导光柱/遮光筒，提高收光面积
- 多放一个 Hub（不同位置、甚至不同载波）做空间分集

### 解码判据（实现要点）

1. 找第一个 mark，长度 2000~2900µs 视为帧头
2. 帧头后 space 350~950µs
3. 逐位读 mark：350~800µs = 0，800~1650µs = 1，位间 space 300~1000µs
4. 位总数必须是 12 / 15 / 20，否则丢弃
5. `cmd = bits & 0x7F`，`dev = (bits >> 7) & 掩码`

## 2. NEC（含 16bit 扩展地址）

| 项 | 值 |
|---|---|
| 载波 | 38kHz |
| 编码方式 | 脉距编码：mark 固定 560µs，用 space 长度表示 0/1 |
| 帧头 | mark 9ms + space 4.5ms |
| 逻辑 0 | 560µs space |
| 逻辑 1 | 1690µs space |
| 位序 | LSB first，32bit = addr + ~addr + cmd + ~cmd |
| 连发帧 | 9ms mark + 2.25ms space（无数据），每 108ms 一次 |

### 常见误判：`BAD-XOR`

固件早期只校验"标准 NEC"（addr 与 ~addr 互补），遇到 **16bit 扩展 NEC**
（如 `0xC480`）会误报校验失败。判定逻辑应该是：

```
cmd 与 ~cmd 互补 → 是合法 NEC 帧
addr 与 ~addr 互补 → 8bit 地址（标准 NEC）
否则             → 16bit 地址（NEC-EXT）
```

## 3. 通用坑

| 现象 | 原因 | 对策 |
|---|---|---|
| 同一帧每次算成不同指纹 | 时序抖动 ±60µs，按原始微秒算哈希不稳 | 用解码后的 `dev/cmd` 当指纹 |
| 一按键触发 8 次 | 遥控器/音箱按住会连发 | 1.2s 同键去抖 |
| 偶发丢解码 | 环境光（阳光/白炽灯含红外） | 遮光筒、要求两帧一致 |
| 距离一远就丢 | 载波不匹配（40k vs 38k）或角度偏 | 换头 / 加透镜 / 多 Hub |
