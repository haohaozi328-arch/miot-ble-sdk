# cube_adv —— 小米魔方控制器（XMMF01JQD / PID 0x04E1）小白版

米家能添加、能记录动作的最小固件。**580,832 B，零告警。**

## 这台的特殊之处

魔方的 spec 几乎是空的 —— `jiqid.robot.cube` 只有服务 1（Device Information：
厂商/型号/SN/固件），**没有任何属性、事件或 action**。所以：

- 不需要铺 spec 属性表（`miot_device_attach(&s_dev, NULL, 0, ...)` 就够）；
- 动作全部走 **MiBeacon 老对象 `0x1001`**（3 字节），绑定后靠加密广播上报；
- App 页面是「动作记录 + 自动化触发器」，不读属性。

## 对象号

| 对象 | 长度 | 含义 |
|---|---|---|
| `0x1001` | 3B | 动作：byte0 `00`=right（顺时针）/ `01`=left（逆时针），后两字节步进/角度 |
| `0x100A` | 1B | 电量 %（标准对象）|

依据：XiaomiGateway3 `devices.py` 里该设备的解码器

```python
BLEMapConv("action", "sensor", mi=4097,
           map={"000000": "right", "010000": "left"})
```

`mi=4097` = `0x1001`，payload 3 字节 —— 与本工程一致。

## 参数

| 项 | 值 |
|---|---|
| PID | `0x04E1`（pdid 1249）|
| 广播名 | `CUBE` |
| NVS | `cube` |
| MAC | `10:00:3B:CE:76:03`（后缀 0x76 / 0x01）|

## 操作

| 按键 | 动作 |
|---|---|
| 短按 BOOT | 翻转 **right** → `0x1001 = 00 00 00`（连播 3 帧）|
| 双击 BOOT | 翻转 **left** → `0x1001 = 01 00 00`（连播 3 帧）|
| 长按 5 秒 | 擦 NVS，恢复出厂（可重新添加）|

空闲时每 3 秒播一帧电量（`0x100A`）。**空闲帧里不塞动作** —— 否则 App 每帧都记成一次动作。

## 待验证 / 后续

1. 绑定流程（未绑定发 hello 帧 + 请求被连接位，同 pir2s）；
2. 短按后 App 的「动作记录」是否出现 right/left；
3. 若通道成立，再按 App 自动化里的动作列表补齐其它动作
   （翻转 90°/180°、摇一摇、敲击两次、推一下）—— 这些的 payload 编码还没有权威样本，
   需要按 App 实测逐个试，不要盲猜（盲塞会污染网关的边沿计数）。
