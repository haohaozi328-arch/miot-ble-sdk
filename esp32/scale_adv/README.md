# 米家体脂秤 S400（MJTZC01YM）可绑定固件 —— ESP32-C3

**可以直接编译烧录、被米家 App 添加、能称一次并出完整体重/体脂报告的完整固件工程。**
与 [`../thermo_gatt`](../thermo_gatt) 同一套骨架（认证 + GATT 0xFE95），多了秤特有的
「7 帧节流上报」和「13.1 sync 应答」。

- 目标芯片：ESP32-C3（USB-Serial/JTAG 直连，一根 Type-C 线即可）
- 模拟型号：米家体脂秤 S400 `MJTZC01YM`，PID **0x30D9**
- 数据通道：**GATT 会话**（App 连上来拿数据）；广播只发电量心跳 / 未绑定 solicited
- 上报内容：体重（3.1005，kg×10）/ 阻抗（3.1006）/ 电量（3.1003/13.10）+
  一次称重的 7 帧事件（8.1 过程流、8.2 结果、11.1022、11.2/11.3 属性变更）

> **2026-11-14 实机验收通过**（MAC `10:00:3B:CE:5C:03`）：绑定一次过 →
> 设备页 `13.1 sync`（267B）应答 5 个 out → App 点「测量」触发 `ACTION 10.1` →
> `weigh step 1/7 … 7/7` 全部 `rc>0` → 报告出 64.5kg，0 次崩溃。

## ★ 烧之前必须确认的两个配置

`main/` 里的代码不是全部，**协议解析跑在 NimBLE 的 host 任务里**，默认栈不够：

```ini
# sdkconfig.defaults（本工程已带，别删）
CONFIG_BT_NIMBLE_HOST_TASK_STACK_SIZE=8192   # 默认 4096 → spec 解析栈溢出
CONFIG_ESP_MAIN_TASK_STACK_SIZE=8192         # 默认 3584 → 登录后处理 GET 也炸
```

栈溢出在 App 侧的表现是「**点测量一直重新连接**」：芯片 `Guru Meditation
(Stack protection fault)` 复位 → App 重连 → 再崩。如果你从别的工程拷了
`sdkconfig.defaults`，务必把这两行带过来。

另外 `gatt_miot.c` 里的 12 条特征（`0001/0002/0004/0010/0013/0014/0016/0017/0018/0019/001A/001B`）
必须与真机一一对应：少一条，App 服务发现后就走另一套分支，登录完一条 GET 都不发。

## 什么时候会"称一次"

| 触发 | 等价于真机 | 行为 |
|---|---|---|
| **BOOT 短按**（手机已连） | 人踩上秤 | 立刻推 7 帧序列（250ms/帧） |
| **BOOT 短按**（手机没连） | 离线称重（说明书步骤④） | 落库 + `13.6` 计数 +1 + 广播 solicited `0x5B` 10 分钟；**下次连手机时整段 7 帧重放**，App 直接出报告 |
| **App 里点「测量」** | 点插件按钮 | 插件不给设备发指令，唯一痕迹是 ACTION 10.1；收到后等 4s 用慢节奏推（1800ms/帧） |
| BOOT 按住 5 秒 | 长按复位 | 擦 NVS 恢复出厂 |

体重/阻抗在 64.5kg↔63.8kg↔65.2kg 三组之间轮换，方便在历史里看到多条独立记录。


```bash

```

## 米家添加

1. 米家 → **+** → **添加设备** → 附近设备出现体脂秤（广播名 `MJJ`）
2. 添加完成后打开设备页：App 会连上来做一次 13.1 sync（串口可见 `REGISTER/LOGIN COMPLETE`）
3. 页面停住不动就直接短按 BOOT —— 等价"人踩上去"

## 验收清单

| 步骤 | 你应该看到 | 判据 |
|---|---|---|
| ① 烧完复位 | `host synced … bound=0`，广播 FC `70 2A` | 未绑定 + solicited |
| ② 米家添加 | `REGISTER COMPLETE (0x11)` → `bound=1` | 云端下发 did 才算成 |
| ③ 打开设备页 | 无卡死；串口可见 `spec ACTION siid=13 aiid=1` 并有 5 个 out | 13.1 sync 推进了同步流程 |
| ④ 短按 BOOT | `weigh-in start 64.500kg …` → `weigh step 1/7 … 7/7` → `weigh-in done` | 7 帧按 250ms 节流，不连发 |
| ⑤ App 页面 | 体重出现、报告页出体脂率等指标 | 云端 code:0，记录进历史 |
| ⑥ 再按两次 BOOT | 63.8kg / 65.2kg 两条新记录 | 每次是独立记录，不是覆盖 |
| ⑦ 断开手机后按 BOOT | `offline weigh-in … solicited=1 10min` | 手机不在场也能"称"，等网关来取 |
| ⑧ 点 App「测量」 | `App ACTION 10.1 …` → 4s 后 7 帧慢节奏 | 页面切到"请上秤"后数据才到 |

## 已知边界

- **MAC 默认是派生出来的**（`USE_CUSTOM_MAC 1`）：米家按 MAC 去重，这颗芯片的物理 MAC
  已被 `t3pro_adv` 绑成温湿度计 3 Pro，直接用会扫不到。本工程派生 `10:00:3B:CE:5C:01`
  → 空中 `…:5C:03`。扫不到就换个没绑过的 `BASE_MAC_B4` 重烧；全新芯片可把宏置 0 用物理 MAC。
- **NVS 命名空间 `scale`**：与 multi_dev 的 `miot`/`miotN` 隔离，不会读到别的设备的 did/bind_key。
- **时间以手机为准**：板上没有 RTC，先用编译时刻当锚点（误差 = "编译→上电"的间隔，
  实测慢 26 分钟），App 每次 `13.1 sync` 会带手机当前时间（piid=4），拿到就置 `s_ts_off`
  整段校准。所以**记录时间不依赖 bin 的新旧**，但首次连手机之前的那条会偏。
  （填 0 会被云端判非法：报告页显示 1970 + 「服务器异常」）
- **离线记录 8 条环形队列 + NVS**：连按多次 BOOT 逐条入队（满 8 条丢最老），
  连上手机后逐条补传、逐条清 `13.6` 计数；掉电/重启不丢（官方说明真机可存 160 条）。
- **「待认领数据」需要真网关/云端**：`8.2` 的 `weightDoneStatus` 打成 `2`(userError) 时，
  App 只弹「是你吗/选择用户」，不认领就整条丢弃（15:45 实测：强杀 App 后记录消失、
  待认领仍空）。该页面靠云端/网关上传通道产生，跟 `known-issues §2.2` 同源。
  开关在 `app_main.c` 的 **`OFFQ_REPLAY_STATUS`**：`0`=进历史（默认，BLE 直连唯一可用），
  `2`=报未识别（接上真网关取数后再改）。底层能力：`scale_s400_report_step_ex(..., status)`。
- **一次称重只落一条记录**：真机会有连续多帧稳定值，本工程是"一次触发一条"。
- **抱婴称重 / 平衡测试未适配**（10.1 work-mode 支持读，但没有对应称重流程）。
- **访客模式未验证**（BLE 直连下走不通，见上条）。
- **体重是模拟值**，没有接真实称重传感器；接真传感器只需把 `k_wcycle` 换成实测值，
  单位必须是**克**（内部再换算成 kg×10 —— 直接塞克会变成 6450kg 超量程，页面停在"上秤"）。

## 协议要点（改代码前必看）

1. **7 帧必须节流**：App 的 ag2 接收窗口同一毫秒只吃一帧，连发会整帧丢。节流表见
   `k_wgap` / `k_wgap_slow`。
2. **13.1 sync 必须回 5 个 out**：离线消息数 / SN / MAC / 固件 / 电量。只回 respCode
   时 App 开屏停住不动（`miot_device_action_out` 的强符号实现就是干这个）。
3. **8.2 结果帧是 28 字段字符串**，插件按下标取 `[3]=体重` `[4]=心率` `[6]=设备时间`
   `[7]=体脂率` `[8]=骨骼肌`，字段数不能删。
4. **done 必须放在结果之后**：先发 done 插件会提前收掉称重流程，后面的 8.2 没人接。
