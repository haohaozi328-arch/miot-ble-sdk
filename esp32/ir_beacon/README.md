# ir_beacon — 用红外当"物理暗号"信道

> 这是**最早的单功能验证工程**（只有"收红外 + 解码 + 串口打印"）。
> 完整方案（1 + N 总线、继电器节点、上云回传、选型清单）见 [`../ir_bus/`](../ir_bus/)，
> 设计文档在 [`../ir_bus/DESIGN.md`](../ir_bus/DESIGN.md)。本工程保留作最小可读示例
> 和 `listen_ir2.py`（带码表实时翻译的串口监听）。

把小爱音箱（内置红外）当成**单向物理信道的发射端**：音箱发出某组冷门红外码，
ESP32 + VS1838B 接收解码后执行自己的逻辑。全程不碰米家协议、不需要网关、
不需要云端授权——因为用的就是音箱的原生红外功能。

```
语音 / 米家自动化
      ↓（云端识别下发，不可控但也不需要控）
小爱音箱 内置红外 LED（38kHz）
      ↓（空气，直线，无回执）
VS1838B（38kHz 解调，输出基带）
      ↓
ESP32-C3 GPIO3 → RMT 捕获 → NEC / SIRC 解码
      ↓
GPIO4 翻转（继电器 / 指示灯 / 触发脚）
```

## 接线

| 器件 | 引脚 | 接到 ESP32-C3 |
|---|---|---|
| VS1838B | VCC | 3V3 |
| VS1838B | GND | GND |
| VS1838B | OUT | **GPIO3**（10k 上拉到 3V3，可选串 100Ω） |
| 继电器模块 | IN | **GPIO4** |
| 继电器模块 | VCC / GND | 5V（或 3V3，看模块）/ GND 共地 |

> VS1838B 自带 38kHz 带通与上拉，OUT 可直接进 GPIO。
> 继电器若为低电平触发，把 `on_key()` 里的电平取反即可。

## 已验证的码表（索尼电视 12bit SIRC）

| 触发 | 协议 | dev | cmd | 一次按键的连发帧数 |
|---|---|---|---|---|
| 电源 / “打开电视” | SIRC12 | `0x01` | `0x15` | 8 |
| 音量 + | SIRC12 | `0x01` | `0x12` | 4 |
| 音量 − | SIRC12 | `0x01` | `0x13` | — |

固件里 `POWER` 会**翻转** GPIO4，`VOL±` 只打印事件（方便挂别的动作）。
同一键 1.2s 内只触发一次，用于吃掉连发帧。

## 支持的解码

| 协议 | 判据 | 输出 |
|---|---|---|
| NEC（8bit 地址） | 帧头 9ms / 4.5ms | `NEC addr=0x.. cmd=0x..` |
| NEC-EXT（16bit 地址） | 同上 | `NEC-EXT addr=0x.... cmd=0x..` |
| 索尼 SIRC 12/15/20bit | 帧头 2.4ms / 0.6ms，位宽编码 | `SIRC12 dev=0x01 cmd=0x15` |
| 其它 | — | `leader=A/Bus` + 完整时序（供下机解码） |

## 怎么用

### 1. 语音触发

对音箱说“小爱同学，打开电视”——只要米家里给该音箱添加过**索尼电视**红外遥控器即可。

### 2. 自动化触发（不用开口）

米家 → 自动化 → 新建：

- 如果：温湿度计 温度 > 28℃
- 就执行：小爱音箱 → **自定义指令** → 填“打开电视”

音箱会把这句话当语音执行，红外码照发，ESP32 照收。

### 3. 换一套码（避免和家里真设备撞车）

选一个**家里绝对没有**的品牌（本项目用索尼电视）。同一个品牌在
“手机万能遥控器”和“小爱音箱红外”里选，码是一致的。

## 编译 / 烧录 / 监听

```bash
./build_ir.sh                       # Docker + ESP-IDF v6.0
python -m esptool --chip esp32c3 -p COM6 -b 460800 \
  --before default-reset --after hard-reset \
  write-flash 0x10000 build/ir_beacon.bin

python listen_ir2.py COM6           # 带自动重连的串口监听
python listen_ir2.py COM6 --reset   # 顺带打一次复位脉冲（自检）
```

### 踩过的坑

1. **ESP-IDF v6.0 把 RMT 驱动拆成独立组件**，`main/CMakeLists.txt` 必须 `REQUIRES esp_driver_rmt esp_driver_gpio esp_timer`，否则找不到 `driver/rmt_rx.h`。
2. **`CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y` 时芯片一复位串口就重新枚举**（VID `303A:1001`），宿主监听必须做自动重连，否则一按复位键脚本就退出。
3. **去重指纹要用解码后的 `dev/cmd`**，不能用原始微秒时长——红外时序抖动 ±60µs，同一帧会算出不同指纹，去重直接失效。
4. **万能遥控器“匹配向导”每按一次换一套码组**（dev 在 1/3/9 之间跳），必须点“有反应”锁死码组，否则永远拿不到固定码。
5. 固件早期把非标准 NEC 一律报 `BAD-XOR` 属误报——`0xC480` 是 **16bit 地址的扩展 NEC**（cmd/~cmd 互补成立）。

## 局限（老实说）

- **单向广播，没有回执**：ESP32 不知道对方是否真的执行了。
- 触发链仍走云端（语音识别、自动化下发），延迟约 0.5~2s，不是局域网直连。
- 红外是直线传播，接收头视角约 ±45°，中间不能有遮挡；阳光/白炽灯有红外干扰。
- 若家里真有同品牌设备，会被一起触发——所以必须选冷门品牌。
