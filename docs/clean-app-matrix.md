# 纯净 App 兼容矩阵 —— 官方原版米家 App，不装任何模块

> 目的：回答一个问题——**别人拿到这台设备，用官方原版 App 能不能添加成功？**
> 结论只取决于设备档案走哪条认证路径，与固件是谁编译的无关。

## 认证路径只有三种

| 路径 | 触发依据 | 谁校验 | 本 SDK 已实现 |
|---|---|---|---|
| **标准认证**（ECDH P-256 REGISTER + HKDF LOGIN） | 广播 FC 的 authMode = 2 | 设备端本地完成，云端只按 PID 建档 | ✅ 完整 |
| **legacy PSK**（ECDH + `smartcfg-*` 标签的 HKDF，**非**对称挑战应答） | App 按型号判定走 PSK 连接器 | 设备端需实现 PSK 握手 | ⚠️ **已实现，未实测**（[帧格式与开关](psk-auth.md)） |
| **广播型**（MiBeacon，不建连接） | 无 GATT 会话 | 网关收广播即可 | ✅ 完整 |

关键事实：**走哪条路径由 App 按型号决定，不由设备挑选。**
所以「某型号在纯净 App 下能不能绑」，答案是固定的——与有没有调试模块无关。

## 实测记录（官方原版 App，无 hook / 无模块）

### ① 蓝牙温湿度计2 `0x055B` — 2026-11-07 通过

固件：ESP32-C3，本 SDK 自建 GATT 工程；App：米家国区原版，未装任何模块。

广播帧（Moto G 蓝牙嗅探实测）：

```
30 58 | 5b 05 | 13 | 10 00 3b ce 4d 02 | 10
FC      PID     cnt   MAC                Capability(bit3~4=2 后绑定)
FC bit5=1 含 Capability、bit8=0 未注册 —— 这两个位缺一个，App 就不列设备
```

串口完整序列（两段连接，中间自然断开是正常的）：

```
--- 第 1 段：REGISTER ---
connected conn=1 mtu=23
subscribe attr=19 notify=1 / subscribe attr=16 notify=1
wr 0010 #1 cmd=A2        → CMD_REGISTER(0xA2) -> register flow
wr 0010 #2 cmd=15        → pubkey + devRandom + devConfirm sent
wr 0010 #3 cmd=13        → REGISTER: did stored (utc=1794014291)
                           REGISTER COMPLETE (result 0x11 on 0x0010)
disconnected reason=0x213

--- 第 2 段：LOGIN ---
wr 0010 #1 cmd=24        → spec session ready (keys set)
                           *** session established: spec channel ready ***
                           spec properties pushed (25.6C / 58.0% / batt 88%)
```

判据说明：`result 0x11` 是标准认证成功码；`did stored` 证明 did 来自云端而非本地伪造；
第二段的 `0x24` 是 LOGIN 命令，之后属性推送成功即 spec 通道可用。
全程没有 PSK 类包，也没有 `dispatch: no consumer`。

#### 页面「历史数据」为空不是故障（2026-11-07 实测时间线）

实测：12:17 绑定成功，设备页顶部实时读数立刻有（25.6℃ / 58%），
**下方历史图表一直是「数据为空」；12:52 仍为空；13:05（跨过整点后）突然出现曲线。**

机制（米家 温湿度计2 的固有设计，与固件无关）：

- 历史曲线来自**云端**，数据源是「蓝牙网关收到 MiBeacon 广播 → 上报云端 → 云端按小时聚合」
- 手机 App 直连只提供顶部实时读数（页面那 3 秒 GATT 会话），**不产生任何历史点**
- 因此：设备页若显示「未连接蓝牙网关」，图表必然空；跨过整点、云端积累到 1 个以上小时样本后才会出现点
- 无网关时曲线永远为空，这是型号能力限制，不是固件 bug

配套的两个环境条件（之前踩过）：

- **手机蓝牙开着 / App 占着连接时设备会停播广播**，网关就收不到 → 表现为「连接不上网关」
- 设备离网关太远时广播命中率低，挪到网关 1 米内、拔插网关电源、重启 App 可恢复

同一时段用 PC 端 BLE 扫描复核空口广播（设备侧自查用）：

```
58 59 5b 05 17 02 4d ce 3b 00 10 | 08 07 14 8a f1 | 04 00 00 | c7 e1 1b 59
FC=0x5958  PID=0x055B  cnt  MAC(LSB)              ct            ctr_ext  MIC
```

ct 段在 4B（0x100A 电量）与 5B（0x1004 温度 / 0x1006 湿度）之间轮换，
counter_ext 与 cnt 同步递增 —— 与真机 LYWSD03MMC 同构。

## 本表的口径说明（重要）

- 矩阵按**认证路径**静态判定：标准认证由设备端本地完成，App 原版即可；
  PSK 路径的握手代码已实现（`MIOT_AUTH_MODE_PSK`），但**还缺一次真机实测**，
  所以第 4、5 项只能标「待实测」而不是「能」。实测开关见 [psk-auth.md](psk-auth.md) §6。
- 历史实机记录（`docs/testing.md`）的测试环境曾带有调试辅助模块，
  **不能直接作为"纯净 App 可绑定"的证据**。因此第 7 项标「待复核」。
- 上方「实测记录」章节的每一条都在**无 hook、无模块**的原版 App 下取得，
  带完整串口序列，可直接引用；后续每验一台就往里加一条。
- 上表第 1~3、6 项之所以标"能"，是因为它们的绑定完成标志
  （`REGISTER COMPLETE` / `BOND confirmed`）出现在**设备端**串口，
  且认证流程不含 PSK 步骤。

## 怎么自己复核一遍（20 分钟）

不安装任何模块，用官方原版 App：

```bash
# 1. 删除设备（我的 → 设备管理 → 删除）
# 2. 重启 App，确保没有残留连接
adb shell am force-stop com.xiaomi.smarthome
# 3. 重新扫描添加，观察串口
idf.py -p <PORT> monitor
```

判据：

| 串口 | 含义 |
|---|---|
| `REGISTER COMPLETE (result 0x11)` + `REGISTER: did stored` | 标准认证，纯净 App 通过 |
| 只出现 `CMD_REGISTER(0xA2)` 后无后续 | 可能被要求走 PSK，或 92B 帧解析差异 |
| `PSK: start frame … captured` | 判定为 PSK 设备，握手已开始（看后续 `PSK:` 行） |
| `PSK: unhandled <n>B (psk_state=…)` | PSK 分支收到未识别帧，开 `psk_trace` 抓原始 hex |
| `dispatch: no consumer (pkg=...)` | 两种链都不认的包，通常是对应档案选错了 |
| 完全无认证日志 | App 没连上，先查广播与 GATT |

把结果回填本表并注明 App 版本与账号区域，是对后来者最有用的一条信息。

## 给使用者的实话

如果你要的是「买个板子刷完就能加进米家」，**选第 2 或第 12 项**——
它们的认证路径完全在设备端，不依赖任何未验证环节。
驱蚊器 / 夜灯重绑走 PSK：代码已经实现（与标准认证共用同一套 ECDH，
只换 HKDF 标签，多一帧 `0x04` 签名），但**还没有人跑通过一次真机实测**，
所以现在不能承诺"能加"。愿意当第一个验证者的话，按 [psk-auth.md](psk-auth.md) §6 开
`psk_trace` 走一遍，把串口日志提 issue 即可。
