# 米家 BLE Mesh 配网协议笔记

对米家 BLE Mesh 设备（灯具 / 墙壁开关一类）配网流程做的一次完整协议观察与工程实践记录。

这一组笔记和仓库主体（`src/` 里的 BLE GATT 直连设备模拟）解决的是**两个不同的接入形态**：

| | 本仓库主体（BLE GATT） | 本目录（BLE Mesh） |
|---|---|---|
| 通信模型 | 手机 ↔ 设备，直连 | 手机/网关 ↔ mesh 网络 ↔ 设备 |
| 身份校验 | 设备证书 + ECDH 会话密钥 | 设备证书 + ECDSA 挑战签名（服务器验） |
| 云端下发 | 不支持（只有手机在附近时可用） | 支持（网关转发） |
| 门槛 | 拿到设备证书即可（本仓库已解决，24 台） | 需要设备私钥签 `pkg4`（见 `06`） |
| 结论 | 可用 | 单靠软件不可复刻，建议走官方模组 |

不是"破解教程"，而是一份**互操作性研究笔记**：协议是怎么设计的、每一帧在做什么、哪些边界是硬性的、以及如果要让自己的硬件接入 mesh，正确的路怎么走。

## 核心结论

1. **配网全链路已完整还原** — 从广播握手到 mesh 网络密钥下发，6 个数据包的顺序、内容、校验点全部对应上了，可以按文档画出精确的时序图。
2. **设备身份由证书 + ECDSA 挑战签名保证** — 服务器验证书链，设备对服务器下发的随机挑战签名，App 把签名原样转交服务器验证。整个链路里没有任何一步会暴露设备私钥。
3. **私钥是产线随机生成并烧录的** — `tools/mesh/derive_test.py` 用 1190 个候选（MAC / 设备信息 / 常见常量 / 各种哈希派生组合）验证了"私钥由公开信息派生"这一假设，全部不中。
4. **真机对单条 BLE 连接有约 20 秒的硬性寿命** — 与连接参数无关，是固件行为。这个特性对任何需要长时间占用设备链路的方案都有决定性影响。
5. **如果要让自己的硬件接入米家 mesh，官方模组是唯一的可持续路径** — 它自带合法证书与私钥，把配网、加密、mesh 收发全部封装在模组内部，开发者只需要通过 UART 处理业务指令。

## 配套工具

都在 [`tools/mesh/`](../../../tools/mesh/)：

| 工具 | 用途 |
|---|---|
| `serial_tail.py` | 串口日志捕获，断线自动重连（与 `tools/serial_tap.py` 的区别：本工具按秒数抓取、退出即止） |
| `btsnoop_parse.py` | Android btsnooz / btsnoop 日志解析 |
| `pkg9_entropy.py` | 从串口日志重组多帧包，做熵值与结构分析 |
| `derive_test.py` | 验证「私钥是否由 MAC / 设备信息派生」，支持 `--sn` 追加自定义种子 |

## 适用范围与局限

- 观察对象是 2025–2026 年固件版本的米家 BLE Mesh 设备，不同批次、不同芯片方案（Telink TLSR825x / Beken 等）在细节上可能有差异。
- 文档描述的是**协议行为**，不包含任何设备身份材料（证书、私钥、真实 MAC），文中所有地址均为占位符。
- 本目录不提供绕过设备绑定校验的方法。如果你的目标是让自己的硬件以 mesh 方式接入米家，请走官方模组或小米 IoT 开发者平台。
