# 米家 BLE Mesh 硬件路线（真网关 + 官方模组）

> 起因：ESP32 复刻 0x0926 Mesh 灯，手机直连必然 `Mesh认证失败 -27`。
> 根因是私有 Provision 的证书链认证，证书链出厂烧录在官方模组里，不可复刻（见 `troubleshooting.md` Q17）。

## 0. 现状盘点

| 项 | 状态 | 说明 |
|---|---|---|
| Mesh 网关 | ✅ 大概率已有 | 小爱音箱 Play 增强版自带「蓝牙网关（Mesh 版）」；需在米家「我的 → 蓝牙网关」确认 **蓝牙 Mesh 网关已开启**、音箱固件为最新 |
| 官方 Mesh 模组 | ❌ 缺 | 证书链只存在于官方模组，这是唯一硬缺口 |
| 设备侧经验 | ✅ 可复用 | MiBeacon 帧（含 bit1 solicited）、PSK 认证、spec 表、调光/色温逻辑，均在 `esp32/meshbulb` 里跑通过 |
| App 侧 | ⚠️ 临时 | 补丁版米家（完整性校验 + mesh 分支旁路）已验证可行，但官方路线不需要它，建议装回原版 |

## 1. 三条路线

### 路线 A：官方模组（唯一能稳定拿到证书链）

流程（小米 IoT 开发者平台 iot.mi.com）：

1. **注册企业**并审核通过（需要营业执照），在企业开发组下添加开发者
2. **创建产品**：联网方式必须选 **BLE-Mesh**
3. **功能定义**：灯类直接选模板
   - 亮度灯 `Lightness`（开关 + 亮度）
   - 色温灯 `Lightctl`（开关 + 亮度 + 色温）
   - 2026-08-06 起的模板调整只影响开关/风扇等品类，**亮度/色温灯模板不变**
4. **固件设置**：开发模式 = 基于小米 IoT SDK；OTA = 含 SDK 固件 OTA；安全芯片 = 未使用；模组型号 = `MHCB05P-B`
5. **资源申请**：
   - 「新建模组采购」→ 采购模组
   - 「申请 SDK」→ 拿到 `partner-gitlab.mioffice.cn/miot/bsp/mijia_ble_mesh.git` 权限（灯类用 `realtek` 分支）

模组选型：

| 品类 | 型号 | 备注 |
|---|---|---|
| 灯类 | MHCB05P-B / MHCB06P-B / MHCB07P | Realtek RTL8762，Flash ~80K / RAM ~48K |
| 灯类 | B09P-B | Silicon Labs BG22，Flash 较小但够灯用 |
| 开关类 | MHCB09P-B | Flash/SRAM 小，**不要用于灯** |

**烧录铁律（踩了就是废片）**
- **禁止全片擦除**：flash 里的证书链一擦即永久丢失，模组无法再配网
- 首次绑定后 **PID + MAC 不可变**，改了配网报 -32；证书链丢失报 -40
- 平台改模板后需等 ≥15 分钟生效

### 路线 B：方案商模组（没有企业资质时的现实选择）

代表性方案：广嵌物联 GQ-MKM6（Telink TLSR8278 方案，米家 Mesh 零火开关）。
- 优点：模组已烧证书链，附带固件框架与硬件设计规范，可小批量买
- 代价：**PID 只能沿用方案商的产品**，等于你的设备在米家里显示成他们的产品；要独立 PID 得他们代申请
- 适合：先跑通「网关配网 + 控制」全链路，再谈自有品牌

### 路线 C：直接买成品灯（最快，但不是 DIY）

买一盏米家 Mesh 灯（如 Yeelight Mesh 灯），用现有音箱网关直接带起来。
如果目标只是「米家里有一盏能开关调光的灯」，这条路 1 天就能完成，且完全不用碰证书链。

## 2. 固件改造点（路线 A，基于 realtek 分支）

1. 拉 `mijia_ble_mesh` realtek 分支，示例工程是**色温灯**（`src/app/mesh/xiaomi_light`）
2. 用平台的「Spec 固件代码自动生成工具」生成 `miot_spec`，替换工程里的同名目录
3. 属性映射（与现有 meshbulb 的 spec 表对齐）：

   | siid.piid | 含义 | 类型 |
   |---|---|---|
   | 2.1 | 亮度 | uint8 1~100 |
   | 2.2 | 色温 | uint32 |
   | 2.3 | 开关 | bool |

4. 上报规范（不遵守会被 SDK 屏蔽）：
   - 周期性属性上报间隔 **≥10 分钟**
   - 自定义属性 10 分钟内 **≤25 次**
   - 网关按 interval(默认 86400)/delta(1) 过滤后才上云，事件不缓存立即上报
5. 重置方式：灯类建议**快速开关 5 次**
6. 现成可搬：`esp32/meshbulb` 里的调光算法、色温换算、按键短按逻辑，直接搬进 `on_property_set/get` 回调

## 3. 验收清单

- [ ] 米家「我的 → 蓝牙网关」：音箱在线、蓝牙 Mesh 网关已开启
- [ ] 米家 → + → 附近设备：设备出现（未配网时 MiBeacon 的 mesh 状态位为 UNREG）
- [ ] 绑定后设备页出现开关 / 亮度 / 色温控件（不是通用「夜灯」页）
- [ ] App 开灯 1~2s 内设备响应；App 状态显示可能滞后（网关缓存，属正常）
- [ ] 断网测试：网关和设备仍供电时，本地自动化是否继续工作
- [ ] 离线判定：网关 1.5 分钟收不到广播即判设备离线（近场）

## 4. 成本与周期（估算）

| 项 | 量级 | 说明 |
|---|---|---|
| 官方模组 | 几十元/片 | 以平台采购报价为准，常要求小批量 |
| 调试器 | 100 元左右 | Realtek 走 Keil + J-Link；Silabs 走 Simplicity Studio + J-Link |
| 企业资质 | 免费 | 需营业执照，审核 1~3 天 |
| 固件开发 | 1~2 周 | 有现成 spec 逻辑可搬，主要是外设与调光算法移植 |

## 5. 如果只是「今天想有盏能用的灯」

不必等模组：把固件 PID 换成非 Mesh 档案（如 `0x03DD` 米家夜灯2），BLE 直连即可绑定，
米家里就是一盏能开关调光的灯。已验证同类 PID（`0x4683`）在同一套固件上 `bound=1`。
代价：它不会是「Mesh 灯」，也不会走音箱网关。

## 2026-11-17 采购落地：乐式 MHCB12G（RTL8762EGF）

用户购入「开关 Ultra 版 1-4 键系列」模块（规格书见微信文件，docx 版已解析）：

| 项 | 内容 |
|---|---|
| 厂商 | 深圳市乐式科技（LeMesh，www.lelight.cn），型号 MK850 |
| 适用模组 | **MHCB12G**（板载天线）/ MHCB12G-IB（外接天线） |
| 芯片 | **Realtek RTL8762EGF**，Cortex-M0+ 40MHz，512KB Flash / 104KB RAM |
| 协议 | BLE / BLE Mesh，**支持小米新一代 MESH2.0 协议** |
| 射频 | TX 7.5dBm typ，RX -97dBm，RX 5.3mA |
| 产品形态 | 86 开关成品固件：1~4 键继电器、遥控对码、互控、凌动/无线开关转换、背光灯、AC 过零检测 |
| 配网 | 米家 Mesh 配网，允许配网窗口 30 分钟；重置 = 任意键 3 短按 + 长按 5s |
| 烧录点 | LOG=P0_3(脚23)、TXD=P3_0(脚12)、RXD=**P3_1(脚13)**、RESET=脚34；串口可烧录可看日志。<br>★2026-11-27 对照规格书原理图订正：RXD 不是 P1_3，而是 **P3_1** |
| 板上测试点 | J1=GND、J2=3V3、J3=RXD、J4=TXD、J5=LOG（**LOG 与 TXD 都是模组输出，别短接**） |

### 接线（按规格书原理图，2026-11-27 整理）

| 目的 | 接法 |
|---|---|
| 只抓日志（先做这步） | `TTL RX ← J5 LOG`（模组 P0_3/脚23），`TTL GND ↔ J1 GND`；**TTL 的 3V3 不接** |
| 双向串口 / 烧录 | `TTL TX → J3 RXD`（模组 P3_1/脚13），`TTL RX ← J4 TXD`（模组 P3_0/脚12），`GND` 共地；RESET 从模组脚34 单独引出用于进下载模式 |
| 供电 | 规格书要求供电芯片 **≥500mA**、纹波 <100mV、独立供电；**禁止用 USB-TTL 的 3V3 给模组供电**（和灯泡同样的复位循环坑）。板子有自身电源时只接 GND，不接 J2 |
| 信号 | SIO / UART 线上按规格书串 **200Ω** 电阻（减驱动、消时序偏差）；天线周围 15mm 净空 |

来源：规格书原理图（`img_07`，测试点 J1~J5、U1 脚位）与「模组设计注意事项」（`img_32`）。

**到货后行动清单（按顺序）：**
1. **先不要烧录任何东西**——出厂证书/私钥大概率在 flash 固定区，先原样在米家绑定成功一次（它是认证模组，理应直接过）
2. UART 接出 LOG/TXD/RXD（3.3V 电平！），抓启动与配网日志
3. 米家配网全程抓包（手机+ESP32-C3 嗅探广播 + GATT Proxy 连接），补齐 mesh 配网协议的实测数据——这是 0x0926 死路一直缺的证据
4. 绑定成功后再研究 flash dump（Realtek 8762 读保护状态未知），决定能否提取证书链
5. 对照 ESP32-C3 固件，把 mesh 品类（PID 0x0926 灯）的绑定流程在认证模组上复现一遍

**风险**：MHCB12G 是开关固件（继电器+按键），要当"灯"用需换 PID 或自制固件；换固件 = 动证书区，先 dump。
