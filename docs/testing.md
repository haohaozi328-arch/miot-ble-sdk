# 逐设备实机验证清单

> 目标：对 SDK 覆盖的 10 台设备逐台做米家 App 实机回归。
> 每台记录：结果（✓/✗）、日期、备注（异常现象 / App 版本 / 固件版本）。
>
> 通用前置：
> - 测试手机可上网，米家 App 已登录；关闭「消息免打扰」避免弹窗遮挡
> - ESP32-C3 通过 USB 连接电脑（串口日志看解析结果）；烧录方法见各固件工程
> - App 端取证（可选）：带 xpmod 模块的补丁包，拉取
>   `/sdcard/Android/data/com.xiaomi.smarthome/files/xp_dump/net_plugin*.log`

## A. spec 连接型

### 1. 米家体脂秤 S400（`scale_s400`）—— 基准设备

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1.1 | 米家首页 → 「+」添加设备，扫描到「米家体脂秤 S400」 | 扫描列表出现 |
| 1.2 | 点击绑定 | 绑定成功（REGISTER），设备页出现 |
| 1.3 | 进入设备页 | 状态「已连接」；实时体重/历史记录正常显示 |
| 1.4 | **成员管理 → 添加成员**（名字随意）→ 保存后流程提示测量 → 上秤/等自动测量 | 测量完成后记录入库，时间正确、挂新成员名下 |
| 1.5 | 「历史数据 → 全部记录」 | 新记录出现在列表（云端入库成功） |
| 1.6 | App 杀后台重进 → 再看全部记录 | 记录仍在（云端持久化） |

⚠️ **S400 验收必须走「添加成员测重」路径（1.4）。** 设备页「测量/抱婴称重/
平衡测试/访客测量」四个入口在当前米家版本下**无法进入测量页**，原因（2026-11-04
取证定案，设备侧无法修复）：
- 插件订阅的 10.1 work-mode 在云端 spec 中 `access:[]`（无 read/write/notify），
  App JS 框架拦截 setProps（连 BLE 帧都不发）→ 四键跳转静默失败；
- BLE 通道 gatt-access 虽有 read/write，但设备主动推的 op=4（属性变更）因无
  notify 权限被 App 丢弃（传输层 ACK 但 SpecMgr 0 解析，伪装 GET 应答 op=3 同样
  被 tid 校验丢弃）→ 插件 mode 缓存无法刷新 → 自动跳转（mode==0）不触发；
- 插件未实现设备侧离线数据拉取（siid=9 仅有定义无调用），「待领数据」纯云端，
  无网关时云端待领区恒为空。
- 「添加成员」流程的测重步骤在插件内直调 addRecord（bundle 363408），绕过上述
  全部限制 —— 实测（2026-11-03 15:36、2026-11-04 复验）时间正确、成功入库、
  重启后仍在。

串口判据：8.1/8.2/1022 帧全部发出 + App [SpecMgr] 解析（WBHOOK 日志）= 固件侧正常。
