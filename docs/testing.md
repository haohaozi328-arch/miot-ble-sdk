## 0. 免手机的 spec 层回归（host 测试）

不接 BLE、不接 App，直接在电脑上跑编解码与属性表，用于快速回归协议层。

| 测试 | 覆盖点 | 命令（仓库根目录，容器内 gcc） |
|------|--------|------------------------------|
| `test/host_repeller_frame.c` | 设备→App 属性上报帧的 siid/piid/类型码（`BOOL=0 / UINT8=1`） | `gcc -I include src/*.c test/host_repeller_frame.c -o /tmp/t && /tmp/t` |
| `test/host_spec_set.c` | App→设备 `SET` 全链路：可写属性落值、只读属性拒绝、未注册属性拒绝、`SET_REPLY` 的 tid/siid/piid/result；以及 `GET` 回包的对象编码 | 同上，换文件名 |

`host_spec_set.c` 的实测输出（2026-11-08，repeller 档案）：

```
① SET 4.1=true   → reply result=0，repeller_power()=1
② SET 2.1=5      → reply result=1（只读属性被拒，值不变）
③ SET 9.9=1      → reply result=1（未注册被拒）
④ SET 4.1=false  → reply result=0，repeller_power()=0
⑤ GET 2.1/3.1/4.1 → 三对象 result=0，类型 uint8/uint8/bool 全对
```

> 注意：`SET` 请求的对象格式是 `[siid][piid16][type16=纯类型号][len][value]`，
> 与设备→App 方向的 `type16=(type<<12)|len` **不同**，改动时别混。

#### 关键实现要点（踩坑记录，勿回退）
1. **明文接收缓冲 ≥1024B**：App 登录后会发 337B spec 请求（明文 ~327B），旧代码
   `uint8_t pt[256]` + `if (ct_len > sizeof(pt)) return;` 静默吞包 → App 等不到应答
   → 四键点不动。且超限必须打日志（`spec DROP ct=`），不要再静默 return。
2. **一问一答，帧间留空**：SET 应答必须单独先发；属性变更（op=4）延后 ≥800ms 再推。
   同一毫秒连发三帧时，App 的 ag2 接收窗口只吃下第一帧，SET 应答被整帧丢弃。
3. **8.2 idx6 = 设备时间（unix 秒）**：插件 `parseInt(data_arr[6])` → `createTime = time*1000`。
   填 0 会让 `createTime=0` → 云端判非法（toast「服务器异常，请重试」）→ 报告页
   渲染 1970/01/01 08:00，且该记录不进历史列表。
4. **时间基准用编译时刻**：`build_epoch()` 解析 `__DATE__/__TIME__`。编译容器
   （`espressif/idf:v6.0`）TZ 为 **UTC**，`__TIME__` 已是 UTC，**不要再减 8 小时**
   （v75 减了 → 显示 06:5x）。误差 = 「编译→上电」间隔。
5. 设备无 RTC、App 从不写 2.3 current-time、也从不发 `get_properties`（实测 0 次 GET），
   时间只能来自设备自身。
6. **广播帧必须按 31B 预算裁剪，失败前不能 stop 广播**（v85）：`advertise()` 一开始就
   `ble_gap_adv_stop()`，随后 `ble_gap_adv_set_fields()` 一旦返回 **rc=4（EMSGSIZE，
   即帧超 26B）就直接 return**，广播永久停着 → App 扫描/连接撞空窗，表现正是
   **「一直正在连接 → 超时」，多试几次或重启 App 又"好了"**（人体2 每 180s 的
   `0x1017` 心跳帧 27B 触发，串口判据 `adv_set_fields rc=4 (len=27)`）。
   修法三条：① `build_v4_frame` 带 `adv_budget` 参数，帧超预算自动改**无 MAC 形态**
   （FC `48 59`，真机 24B 同款，App/网关按广播源地址归属）；② `set_fields` 失败改用
   最小明文帧头重建，绝不留在 stop 状态；③ 定时器兜底 `!ble_gap_adv_active()` 时用
   电量帧拉起来。驱蚊器状态帧（28B）同样受此影响，已一并修掉。
7. **纯广播型设备的设置页依赖插件自检，与固件无关**（甲醛，2026-11-04）：
   甲醛检测仪登录后 App **一次属性读取都没发起**（没有 spec / GET），页面数据
   全部来自「MiBeacon 广播 → 网关 → 云端」。所以「推帧成功」≠「页面有值」，
   一定要等网关首报（必要时插拔网关 + 重启 App）。
   数据全通后右上角「…」仍点不动、弹「固件版本读取中」：插件是
   `yuemee.airmonitor.mhfd1`，页面开屏时要读 MCU 版本，而云端没有与本项目
   对应的固件版本记录 → 设置入口不放行。
   不影响数据/历史/自动化，属插件侧限制；删设备可改用长按卡片或「我的 → 设备管理」。


串口判据：8.1/8.2/1022 帧全部发出，且 App 侧 `adb logcat | grep -i spec` 能看到
收到帧（官方原版 App 的日志），两者一致即固件侧正常。

## D. 连接型独立工程（GATT 会话为主）

### 14. 体脂秤 S400（`MJTZC01YM`，独立工程 `esp32/scale_adv`）

> PID `0x30D9`。称重序列 / 13.1 sync 应答直接复用 multi_dev 已实测通过的
> `scale_s400_*` 实现，抽成单设备工程后**协议层未改一行**。
> 2026-11-14 实机验收通过（见下），830 行，0 warning。

**2026-11-14 14:1x 实测记录**（MAC `10:00:3B:CE:5C:03`，`_scale7.log`）：

```
rd 0004 → wr 0010 cmd=A4 → wr 0010 cmd=24(LOGIN) → STD LOGIN COMPLETE
spec session ready (keys set) / mtu=247
initial status pushed (weight/time/battery)
spec req seq=0 pt=5B      ← 版本交换
spec req seq=1 pt=267B    ← 13.1 sync，应答 outs=5
spec req seq=2 pt=8B      ← App ACTION 10.1 = 点「测量」
weigh step 1/7 rc=16 … 7/7 rc=24 → weigh-in done
0 次 Guru Meditation
```

**这一步踩了三个坑，都已固化进工程**：

1. **密钥没交给 spec 层** → 7 帧全部 `rc=-1`。`miot_device_set_session_keys()` 原只有
   `multi_dev` 调过，广播型工程不走 spec 通道所以从未暴露。现由主循环在
   `s_auth.logged_in` 时补交，断开时 `session_reset`。
2. **`nimble_host` 栈溢出** → 收到第一条 spec 请求即 `Stack protection fault` +
   `RTC_SW_CPU_RST` 复位，App 侧表现为「点测量一直重新连接」。默认 4096 不够，
   已设 `CONFIG_BT_NIMBLE_HOST_TASK_STACK_SIZE=8192`（`sdkconfig.defaults` 有注释）。
3. 附带：GATT 特征从 8 条补到真机的 **12 条**（补 `0001`/`0016`/`0017`/`0018`，
   `001B` 加 notify），否则 App 服务发现后走另一套分支，登录完一条 GET 都不发。
4. **时间漂移**：板子没有 RTC，`build_epoch()` 用编译时刻当锚点，误差恒等于「编译 →
   上电」的间隔（2026-11-14 实测 14:09 编译、14:35 上电 → 记录全慢 26 分钟）。
   现改为 App 每次 `13.1 sync` 时取 `piid=4` 的 unix 秒做 `s_ts_off` 校准，**手机时间说了算**。
5. **离线称重**：只把体重写进属性表（`3.1005`）不会产生历史记录 —— App 要看到
   8.1 过程帧才会进「称重中」，所以补传必须整段 7 帧重放（见 14.10）。
